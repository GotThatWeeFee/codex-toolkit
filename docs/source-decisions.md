# Source decisions

No root license is included. Retained material remains subject to attribution and repository access controls; this guide does not grant or imply public redistribution rights.

| Source | Decision |
| --- | --- |
| Work `analyzing-dotnet-performance`, `change-explanation`, `codex-working-playbook`, `dotnet-integration-validation`, `evidence-bound-operations`, `project-aware-coding`, `repository-documentation`, `safe-git-integration`, `sql-object-impact-analysis` | Retained as reusable guidance. Change drafting grants no Git permission; live validation and Git actions remain separately authorized. |
| Work `engineering-subagent-pipeline` | Foundation for the consolidated pipeline and 13 roles. |
| Personal pipeline | Its candidate binding, lifecycle, finding disposition/dissent, authorization preservation, evidence distinctions, and optional reviewer teaching improvements prevail. Competing skill and old role names are manually retired. |
| Work/personal/team Jira variants | Consolidated into optional, team-neutral `current-jira-workflow` with capability discovery, measured-time duplicate prevention, readback, and recipient-defined hierarchy/estimation. |
| Personal request-model policy | Reduced to an opt-in example: no mandatory shared model prompt, fixed tier, or unavailable model catalog. |
| Personal `AGENTS`/configuration examples | Short optional examples only; never copied automatically. |
| Personal installer, manifest, verifier, inventories | Retired as a distribution contract; native plugins and bounded role installation replace them. |
| Personal Playwright copy | Excluded; use maintained upstream installation. |
| Work audit helper | Retained only as opt-in metadata tooling with no author path, activation, or hook install; a caller must supply an explicit local `-AuditRoot`. |
| Runtime snapshots/fixtures; Rupert Case QA; system skills, vendor caches, memories, sessions, credentials, trust state, hook configuration | Excluded. |

The Jira plugin has no credentials, account binding, or fixed service permissions. Project-specific rules, architecture, service mappings, internal examples, test data, and operational documents stay in project repositories. The toolkit does not collect them or transfer account state.
